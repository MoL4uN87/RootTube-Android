# RootTube: действия с комментариями YouTube — проект решения (2026-11-17)

## Цель
Пользователь хочет ставить/снимать лайки с комментариев, оставлять собственные комментарии и отвечать на чужие, не уходя в отдельное приложение YouTube. Текущий RootTube отображает комментарии только для чтения через MediaServiceRepository; текущий вход Piped не даёт прав YouTube.

## Рассмотренные подходы
1. Официальный YouTube Data API + Google OAuth: обеспечивает публикацию комментариев/ответов, но не позволяет ставить/снимать лайки комментариев по официальному API. Не решает все требования.
2. Обычный Android WebView с youtube.com: встроен максимально глубоко, но Google не поддерживает авторизацию OAuth во встроенных WebView; высокий риск неработающего входа.
3. **Выбранный вариант: Partial Chrome Custom Tab** (встроенная панель браузера поверх RootTube): взаимодействия выполняются на официальном youtube.com с существующей браузерной авторизацией; при поддержке браузера панель выезжает снизу. Лайки и публикация принадлежат YouTube, а не симулируются в приложении.

## Поведение
- Список комментариев RootTube остаётся прежним (включая русский перевод, AI+ и просмотр ответов).
- Под каждым комментарием добавить доступную кнопку «👍» / «На YouTube» и действие «Ответить». Они открывают официальный YouTube в частичной вкладке с адресом соответствующего видео и, по возможности, ID комментария. Внутри вкладки пользователь сам нажимает «Нравится», повторно снимает лайк или пишет ответ.
- В разделе комментариев добавить кнопку «Написать комментарий», открывающую то же видео на YouTube; пользователь пишет и отправляет комментарий сам.
- При закрытии вкладки RootTube остаётся на прежнем видео и месте в списке. Для обновления добавлена явная кнопка «Обновить» в главном списке комментариев. Автообновления нет: источник не поддерживает стабильное восстановление позиции при перезагрузке глубокой страницы. В ответах исходный родительский комментарий остаётся снимком до возврата к главному списку.
- При первом использовании Google-вход может потребоваться в браузере; Piped-вход не используется как YouTube-вход.
- Если установленный браузер не поддерживает частичную вкладку, он может открыть полноэкранную Custom Tab. Если браузера нет, показать понятную ошибку.

## Техническая реализация
- Использовать AndroidX Browser (`androidx.browser:browser`) и `CustomTabsIntent.Builder.setInitialActivityHeightPx`; не использовать JS-инъекции, подмену User-Agent, извлечение cookies/паролей или неофициальные авторизованные запросы.
- Добавить `YouTubeCommentActions`/URL-builder с проверкой ID видео и комментария и явным HTTPS-доменом `www.youtube.com`, без произвольного URL.
- Обновить `CommentsSheet`, `CommentsMainFragment`, `CommentsRepliesFragment`, `CommentsPagingAdapter`, разметку и RU-строки. Не менять подсистему перевода и воспроизведения.
- Не утверждать, что нативная кнопка лайка сама поставила лайк: она **открывает панель**, где действие делает пользователь.

## Ограничения, тесты и критерии приёмки
- YouTube не обещает стабильную прокрутку к выбранному комментарию по `lc`; тестировать на конкретных видео.
- Проверить: частичная вкладка на Samsung SM-S948B; вход в Google; открытие видео и конкретного комментария; лайк и отмена; публикация комментария и ответа; возврат на то же место; пограничные случаи (нет браузера, нет сети, закрытые комментарии, гость).
- Unit-тесты URL-builder: валидные/невалидные videoId/commentId, экранирование параметров, защита от произвольного URL.
- Если Google-вход или работа YouTube в выбранном браузере неудачны, остановиться и сообщить о блокере до перехода на приватные API.

## Что не делаем
- Не переносим секреты из LibreTube/Piped, не извлекаем браузерные cookies.
- Не отправляем комментарии или лайки автоматически без подтверждения пользователя.
- Не обещаем «один тап = лайк» в родном списке RootTube, поскольку публичный API YouTube этого не поддерживает.
